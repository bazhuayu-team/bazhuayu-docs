先用 `search_templates` 发现模板；确定目标后必须再次精确查询模板，读取本次运行的字段和选项。模板参数会更新，不能复用旧任务里的 `field`、`field_2` 或 `url` 等猜测字段名。

## 参数

三种检索方式一次只能使用一种：

| 参数 | 用途 | 约束 |
| --- | --- | --- |
| `query` | 语义搜索，例如“Amazon 德国站关键词列表” | 可选 `limit`，范围 `1-20` |
| `id` | 精确查询模板 ID | 不可与其他选择器并用 |
| `slug` | 精确查询模板别名 | 不可与其他选择器并用 |

```json
{
  "query": "Amazon 德国站关键词列表",
  "limit": 10
}
```

确定模板后，按 `id` 或 `slug` 再查一次：

```json
{
  "slug": "<模板别名>"
}
```

## 读取实时契约

精确查询的重点是：

- `templateName`：后续传给 `execute_task` 的精确名称。
- `inputSchema`：参数的真实 `field`、控件类型、必填状态和示例。
- `sourceTree`：下拉或多选字段的候选值；应传其中 option 的 `key`，不能传展示文字。
- `executionMode`：优先选择包含 `Cloud` 的模板。
- `outputSchema`：如有提供，可先确认可采集的输出字段。

若是 `Input` 或 `Dropdown`，通常传字符串；`MultiInput` 或 `CheckboxList` 即使只有一个值也传字符串数组。依赖前一项选择的字段会在参数不足时以 `input_required` 和 `sourceOptions` 引导补齐，补齐后用同一模板重新执行。
