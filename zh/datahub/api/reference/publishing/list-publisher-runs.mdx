## 端点

```
GET https://api-datahub.bazhuayu.com/v1/publisher/runs
```

认证：需要 API Key（`Authorization: Bearer <API Key>`）。

对我发布的 App 的每一次调用，最新在前，是发布者用量分析背后的明细面：同样的归属（我拥有的 App，含零 Release）、同样的区间谓词与筛选值，所以任何汇总数字都能钻取到它计入的运行。

这是**白名单视图**，不是调用方的运行对象：它告诉你发生了什么（状态、时间、写回记录数、错误码与消息、调用方支付的数据费），但永远不告诉你是谁调用、传了什么（没有 `input`）、拿到了什么（没有 `dataset_id`、没有记录、没有凭证标识）。调用方继续通过自己的运行列表读取；发布者无法用这里的 `run_id` 打开对方的运行。作者调试运行默认排除；`status` 支持逗号分隔多值。

## 请求

### 查询参数

<ParamField query="data_app" type="string[]">
  只看这些 App，可重复传。
</ParamField>

<ParamField query="status" type="string">
  运行状态，逗号分隔多值。
</ParamField>

<ParamField query="triggered_by" type="string">
  只看一个调用渠道。
</ParamField>

<ParamField query="version" type="string">
  只看钉到该版本的运行。
</ParamField>

<ParamField query="error_code" type="string">
  只看错误码等于该值的运行（发布者用量分析 `group_by=error` 的 `error_code`）。
</ParamField>

<ParamField query="run_kind" type="string" default="production">
  `production`（默认）只看生产流量，`test` 只看我的调试运行，`all` 两者都看。
</ParamField>

<ParamField query="created_from" type="string">
  起点，包含。
</ParamField>

<ParamField query="created_to" type="string">
  终点，不包含。
</ParamField>

<ParamField query="offset" type="integer" default="0">
  分页起点。

范围 ≥ 0。
</ParamField>

<ParamField query="limit" type="integer" default="50">
  每页条数。

范围 1 到 200。
</ParamField>

### 示例请求

```bash
curl \
  -H "Authorization: Bearer $BAZHUAYU_API_KEY" \
  "https://api-datahub.bazhuayu.com/v1/publisher/runs?data_app=carol/reviews-query&status=FAILED&limit=50"
```

### 错误

| HTTP | `code` | `category` | 说明 |
| --- | --- | --- | --- |
| 401 | `unauthorized` | `forbidden` | 缺少或无效的 API Key。 |
| 400 | `invalid-status` | `invalid_input` | `status` 含有词汇表之外的状态值。 |
| 400 | `invalid-run-kind` | `invalid_input` | `run_kind` 不在允许的取值内。 |
| 404 | `app-not-found` | `not_found` | App 不存在、已改名，或对当前凭证不可见（私有 / 分享范围之外）。 |

错误响应统一为 `{"error": {code, category, message, retryable}}`，见<a href="/zh/datahub/api/reference/introduction#错误">错误</a>。
